## Architecture note

This port does **not** expose one REST resource route per domain (e.g. `GET /api/po`, `POST /api/po`). Instead it stands in directly for Apps Script's `google.script.run` bridge: a single endpoint, `POST /api/erp/rpc/<method>`, dispatches to whichever GAS method name the client asks for, with positional args in the JSON body's `args` array (see `app/erp/rpc.py`). Every method below is called exactly the way its GAS original was: `Api.call('methodName', ...args)` for reads, `Api.mutate('methodName', ...args)` for mutations (adds a required `X-Mutation-Id` header for idempotent replay -- GAS's `google.script.run` needed no such header since it has no HTTP retry layer).

**Auth:** the entire `/api/erp/rpc/<method>` bridge is behind `@login_required` (`app/erp/rpc.py`) -- both reads and mutations, not just mutations.

**Response envelope:** every method returns `{success: bool, data: ..., message: str}`, always as HTTP 200 for domain-level failures (`success:false`); HTTP 404 is reserved for an unknown method name, 401 for unauthenticated, 400 for a missing/malformed `X-Mutation-Id` on a mutation.
